# Patch layout

Patches are grouped first by artifact kind (`snaps/`, `rocks/`, `charms/`) and
then by source project, so `git apply --check` runs against the matching
checkout.

The `Upstream tracking` and `Remove when` columns are maintained manually. Add
the Launchpad bug, pull request, or "none recorded" note when a patch is added,
and update the removal condition when the upstream fix lands.

| Directory | Applied to | Applied by |
|---|---|---|
| `snaps/openstack-hypervisor/` | `snap-openstack-hypervisor` | `tools/build_snaps.sh` |
| `snaps/cinder-volume/` | `snap-cinder-volume` | `tools/build_snaps.sh` (local validation; upstream fixes pending) |
| `rocks/rawfile-localpv/` | rawfile-localpv manifest/rockcraft | `tools/build_rock.sh` |
| `charms/` | charm sources | reserved; no current charm patches |

## snaps/cinder-volume

| Patch | Purpose | Upstream tracking | Remove when |
|---|---|---|---|
| `ceph-20.2.4-ppa.patch` | add the LP #2166817 Ceph 20.2.4 PPA and matching client libraries to local snap builds | LP #2166817 (SRU), LP #2166524, LP #2171989 | Resolute/UCA publishes Ceph 20.2.4 and the matching client libraries |

LP #2166817 is the Ceph 20.2.4 SRU/FFE. LP #2171989 covers the 20.2.0
`ceph-common` parser failure on aes256k keys generated by Ceph 20.2.4+;
LP #2166524 covers malformed aes256k CephX key generation/parsing in
`ceph-common` 20.2.0. LP #2169774 covers the incorrect `20.2.4+ds` source
tarball repack. The local cinder-volume snap must use matching 20.2.4 client
libraries to avoid the aes256k parser mismatch.

The old `cinder-volume-ceph-library-triplet.patch` was removed. Current
upstream uses `$CRAFT_ARCH_TRIPLET_BUILD_FOR` in the snap app library path, so
that patch no longer applies.

## rocks/rawfile-localpv

| Patch | Purpose | Upstream tracking | Remove when |
|---|---|---|---|
| `s390x.patch` | add the s390x platform, link `grpcio` against Ubuntu OpenSSL, and drop the s390x-unavailable FIPS module | none recorded | upstream rawfile-localpv supports s390x |

`tools/build_rock.sh` discovers and applies every `*.patch` under
`patches/rocks/<rock>/`. Phase 02b only imports the resulting rock/tag into the
Kubernetes containerd store.
